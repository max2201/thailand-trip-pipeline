# Подробные отчёты по кнопке на сайте

Это инструкция для Claude, который дежурит у очереди. Его запускает запланированная задача раз в час, с 8:00 до 24:00 по Красноярску (UTC+7).
Человек на сайте нажимает «Подробный отчёт», и в Firestore появляется заявка `trips/thai2026-6hvxyynirl/reports/<id>`. В ней остановка (`stop`), отели, которые он отметил плюсом (`hotels`), и его имя (`name`).
Задача: прочитать **все** отзывы этих отелей и их карточки на trip.com и написать подробный сравнительный отчёт. Сайт покажет его в окне сам, как только статус станет `ready`.

Все команды запускаются из корня репозитория. Python 3.10 или новее, нужен `requests` (`pip install -r requirements.txt`).
Отчёт пишется по-русски, для человека, который выбирает, где жить в поездке.

## 0. Дежурство

```
python run.py report wait
```

Команда ждёт до 9 минут и проверяет очередь каждые 30 секунд. Она печатает одно из трёх:

- `ЗАЯВКА {"_id": …}` — есть работа, переходи к шагу 1;
- `ПУСТО — вызови report wait ещё раз` — вызови её снова;
- `ДЕЖУРСТВО ОКОНЧЕНО` или `ОШИБКА…` — закончи работу одной строкой, без отчёта.

Каждый запуск дежурит 60 минут с первого вызова, потом его сменяет следующий.
Вызывай Bash с таймаутом 600000 мс.
Между вызовами ничего не пиши и ничего не делай, это экономит лимиты.

После того как заявка обработана (шаг 6), снова вызывай `report wait`, пока не увидишь `ДЕЖУРСТВО ОКОНЧЕНО`.

## 1. Забрать заявку

```
python run.py report take <id>
```

Если команда печатает «УЖЕ В РАБОТЕ», «ТОЛЬКО ЧТО ЗАБРАЛ ДРУГОЙ» или «ЗАКРЫТА», значит заявку взял другой запуск. Тогда просто вернись к `report wait`.

## 2. Скачать данные

```
python run.py report fetch <id>
```

Займёт 1–10 минут. Таймаут Bash ставь 600000 мс; если не уложится — запусти в фоне и дождись.
Результат лежит в `work/<id>/`:

- `plan.md` — список отелей и частей отзывов;
- `<отель>/details.md` — карточка отеля с trip.com: удобства по группам, правила, завтрак, номера, что рядом, оценки, метки trip.com, цена на наши даты;
- `<отель>/reviews/NN.txt` — все отзывы с текстом, по 150–200 в части, у каждого номер `#i`, оценка, дата, тип поездки, номер, язык;
- `<отель>/meta.json` — служебные данные.

## 3. Разметить отзывы (самая долгая часть)

Каждую часть `reviews/NN.txt` нужно прочитать целиком и записать два файла:

- `<отель>/tags/NN.txt` — по строке на **каждый** отзыв части;
- `<отель>/notes/NN.json` — что конкретно говорят по каждой теме.

Части не зависят друг от друга. Если есть инструмент Agent, раздай их субагентам по 1–2 части на каждого, до 8 одновременно.
Каждому субагенту дай полный путь к части и путь к этому файлу и попроси выполнить раздел «Задание разметчика» ниже.
Если субагентов нет, размечай сам, часть за частью.

Перед этим обнови статус, чтобы человек видел ход работы:

```
python run.py report status <id> "Читаю отзывы: 0 из N частей"
```

Повторяй эту команду после каждых нескольких частей.

### Задание разметчика

Прочитай файл части `…/reviews/NN.txt` полностью. Отзывы бывают на любом языке; понимай их как есть.

**Файл 1** — `…/tags/NN.txt` (рядом с папкой `reviews`, имя файла то же).
Ровно одна строка на каждый отзыв части, в порядке номеров: `номер: тема± тема± …`.
Знак после темы: `+` — хвалят, `-` — ругают, `~` — и то и другое или нейтральный факт.
Если отзыв ни о чём конкретном («всё хорошо»), строка будет `номер: -`.
Пропускать отзывы нельзя.

Пример:
```
17: loc+ clean+ noise- breakfast~
18: staff+ value+
19: -
```

Темы (ключ — что сюда относится):

- `loc` — расположение и окрестности: до чего близко, транспорт, еда и магазины рядом, можно ли ходить пешком
- `clean` — чистота: номер, бельё, ванная, уборка
- `room` — номер: размер, состояние, ремонт, мебель, планировка
- `bed` — кровать и сон: матрас, подушки, удобно ли спать
- `bath` — ванная и вода: душ, напор, горячая вода, слив, туалет
- `ac` — кондиционер и климат
- `noise` — шум и звукоизоляция: улица, соседи, бары, стройка, тонкие стены
- `staff` — персонал и сервис: ресепшн, дружелюбие, помощь, английский
- `checkin` — заселение, выезд, бронь: ранний заезд, поздний выезд, депозит, проблемы с бронью
- `breakfast` — завтрак: есть ли, выбор, вкус, часы, цена
- `food` — ресторан, бар, рум-сервис (кроме завтрака)
- `pool` — бассейн
- `gym` — спортзал, спа, массаж
- `view` — вид и окна, в том числе номера без окон
- `wifi` — интернет
- `amen` — удобства в номере: холодильник, чайник, ТВ, сейф, косметика, полотенца, розетки
- `common` — общие зоны: лобби, лифт, сад, коворкинг, прачечная, крыша
- `value` — цена и соотношение цены и качества
- `insects` — насекомые: тараканы, клопы, муравьи, комары
- `smell` — запахи, сырость, плесень
- `safety` — безопасность
- `transport` — трансфер, такси, парковка, прокат
- `family` — дети и семья
- `other` — важное, что не попало в темы выше

**Файл 2** — `…/notes/NN.json`: только темы, которые встретились в части.

```json
{
  "noise": {
    "good": ["тихо ночью, хотя рядом бары (4)"],
    "bad": ["тонкие стены, слышно соседей и коридор (6)", "по выходным музыка с крыши соседнего бара до часу ночи (2)"],
    "quotes": [{"i": 17, "s": "-", "t": "Стены картонные: слышали, как сосед говорит по телефону."}]
  }
}
```

- `good` и `bad` — конкретные наблюдения по-русски, сгруппированные. В скобках — сколько отзывов этой части об этом говорят.
  Пиши конкретику: часы, цены, расстояния, названия мест рядом, номера этажей и типы номеров, если их называют.
  Не пиши общих слов вроде «хорошая чистота».
- `quotes` — 1–3 самые показательные цитаты по теме.
  `i` — номер отзыва, `s` — `+`, `-` или `~`.
  `t` — цитата по-русски, до 200 знаков. Если отзыв на другом языке, переведи близко к тексту.
- Отдельно отмечай то, что важно путешественнику: насекомые, плесень, кражи, обман с депозитом, стройку рядом, проблемы с бронью. Даже единичные случаи, с датой отзыва в формулировке.

В конце проверь: в `tags/NN.txt` столько же строк, сколько отзывов в части, и номера совпадают.

## 4. Посчитать

```
python run.py report tally <id>
```

Команда посчитает по каждому отелю и теме точные числа: сколько отзывов упоминают тему, сколько хвалят и ругают, то же за последний год, долю.
Результат лежит в `<отель>/stats.json`, а все заметки разметчиков собраны в `<отель>/notes.json`.

Если команда пишет «ЕСТЬ ПРОПУСКИ», доразметь указанные части и запусти её снова.

## 5. Написать отчёт

```
python run.py report status <id> "Пишу отчёт"
```

Прочитай по каждому отелю `details.md`, `stats.json` и `notes.json`. Потом запиши `work/<id>/report.json` в формате ниже.
Цифры (количество, доли, оценки, цены, расстояния) **не пиши** — `report put` подставит их сам из подсчёта.
От тебя нужен смысл: что именно говорят люди, чем отели отличаются и что из этого следует.

```json
{
  "summary": [
    "2–5 абзацев: общий вывод по сравнению. Кто лучший по совокупности и почему, где главные компромиссы, на что обратить внимание. Ссылайся на конкретику из отзывов."
  ],
  "picks": [
    {"title": "Лучший сон и тишина", "text": "Отель — почему, одной-двумя фразами"},
    {"title": "Лучший завтрак", "text": "…"},
    {"title": "Лучшее расположение", "text": "…"},
    {"title": "Больше всего за свои деньги", "text": "…"}
  ],
  "compare": [
    {"group": "Номер", "label": "Площадь и кровать стандартного номера", "cells": {"<id отеля>": "30 м², king-size", "<id>": "…"}, "best": [<id>]},
    {"group": "Завтрак", "label": "Завтрак", "cells": {"<id>": "шведский стол 6:00–10:30, отдельно ≈350 ₽; хвалят выбор", "<id>": "нет"}}
  ],
  "hotels": {
    "<id отеля>": {
      "verdict": "3–5 предложений: главное об отеле по итогам всех отзывов",
      "fit": "кому подойдёт",
      "unfit": "кому не подойдёт",
      "pros": ["главные плюсы, 4–8 пунктов, с конкретикой"],
      "cons": ["главные минусы и риски, 3–8 пунктов, с конкретикой; если минусов почти нет — так и напиши"],
      "cats": {
        "<ключ темы>": {
          "good": ["что хвалят — сведённые и очищенные от повторов пункты из notes.json, самое частое первым, с числом отзывов в скобках"],
          "bad": ["что ругают — так же"],
          "quotes": [{"i": 17, "s": "-", "t": "цитата по-русски"}]
        }
      },
      "sections": [
        {"title": "Номера", "items": ["каждый тип: площадь, кровать, окно или вид, что есть в номере, что пишут гости о номерах этого типа"]},
        {"title": "Завтрак", "items": ["включён или нет, формат, часы, цена, что хвалят и ругают"]},
        {"title": "Бассейн", "items": ["…"]},
        {"title": "Спортзал, спа, массаж", "items": ["…или «нет»"]},
        {"title": "Рестораны и бары", "items": ["…"]},
        {"title": "Удобства отеля", "items": ["всё важное из карточки по группам: что бесплатно, что платно, чего нет"]},
        {"title": "Фишки отеля", "items": ["необычное и полезное: крыша, коворкинг, велосипеды, трансфер, прачечная самообслуживания…"]},
        {"title": "Правила и деньги", "items": ["заезд и выезд, депозит, оплата, дети, питомцы"]},
        {"title": "Что рядом", "items": ["места рядом с расстояниями, что пишут про район днём и ночью"]}
      ]
    }
  }
}
```

Требования:

- **`hotels`** — каждый отель заявки. Ключ — id строкой.
- **`cats`** — каждая тема, которую упоминают хотя бы 3 отзыва (список тем — в `stats.json`). У темы 2–8 пунктов в `good` и `bad`, если есть что сказать, и 1–3 цитаты.
  Числа в скобках бери из `notes.json` (суммируй по частям) и не завышай.
- **`compare`** — 15–30 строк по всем отелям сразу.
  - Номер: площадь, кровать, окно или вид, состояние по отзывам.
  - Завтрак.
  - Бассейн (размер, часы, отзывы).
  - Спортзал, спа и массаж.
  - Ресторан и бар.
  - Wi-Fi.
  - Парковка, трансфер, прокат.
  - Прачечная.
  - Заезд и выезд.
  - Депозит.
  - Чистота, шум и персонал по отзывам — словами, без процентов: проценты добавятся автоматически.
  - Главная фишка и главный риск.

  В ячейке — коротко, до 120 знаков. `best` — id лучших в строке, можно пропустить.
- Цену, расстояние, оценки и долю жалоб не дублируй: эти строки `put` добавит сверху сам.
- Пиши честно. Если данных нет («trip.com не указывает»), так и пиши, не придумывай.
- В заявке может быть один отель. Тогда `compare` всё равно нужен (одна колонка), а `summary` — вывод о нём.

## 6. Отправить

```
python run.py report put <id>
```

Команда проверит `report.json`, подставит цифры и отправит отчёт на сайт.
Если она пишет «НЕ ОТПРАВЛЯЮ», исправь то, что указано, и запусти снова.
После «ОТПРАВЛЕНО» вернись к `report wait` (шаг 0).

Если что-то сломалось совсем (trip.com не отдаёт отзывы, нет ни одного отеля), закрой заявку с понятной человеку причиной:

```
python run.py report fail <id> "trip.com не отдал отзывы, попробуйте позже"
```

## Проба без базы

`REPORT_DRY=1` перед любой командой берёт заявку из `work/<id>/_doc.json` и пишет изменения туда же, Firestore не трогает.
Пример: `mkdir -p work/try && echo '{"stop":"s3","hotels":[28864890],"name":"Тест","t":1,"status":"queued"}' > work/try/_doc.json`.
